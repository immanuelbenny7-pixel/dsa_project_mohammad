📚 Data Structures in "Pump Shift"

1

Queue — FIFO Customer Line

Enqueue: O(1) • Dequeue: O(1)

Cars arriving at the station join the back of the waiting line and must be served in the order of their arrival. A First-In, First-Out (FIFO) Queue guarantees fairness: the car waiting the longest at the front is always served next at the pump island.

customerQueue.enqueue(newCar); // Car joins at rear (slot 4)
const servedCar = customerQueue.dequeue(); // Leaves front (slot 1)
2

Stack — Transaction History & Undo

Push: O(1) • Pop: O(1)

When a transaction completes, it is pushed onto the transaction stack. A Last-In, First-Out (LIFO) Stack ensures that when the attendant needs to reverse an accidental or incorrect sale, the most recent transaction is popped first, rolling back the cash and restoring the exact litres of fuel dispensed.

transactionStack.push(sale); // Record new payment on top
const lastSale = transactionStack.pop(); // Undo rolls back latest sale
3

Hash Map — Fuel Prices & Car Orders

Lookup: O(1) Constant Time

Rather than searching through lists, fuel types (regular, premium, diesel) and unique vehicle orders (e.g. CAR-102) are mapped via Hash Maps for instant $O(1)$ lookups. This dynamically calculates prices and validates orders without hardcoding details into the interface.

const fuel = fuelHashMap.get('regular'); // Returns { price: 1.45, stock: 350 }
const order = carOrderMap.get('CAR-102'); // Returns { fuelType, targetLitres }
4

Array / List — Daily Sales Analytical Report

Append: O(1) • Aggregation: O(N)

Each validated sale is appended to the daily sales ledger. At the end of the shift, the system iterates through this array to aggregate total revenue, calculate fuel volume breakdowns, determine the average ticket, and tally mistakes. If a sale is undone via the stack, the matching array entry is reversed to maintain full financial audit integrity.

5

Singly Linked List — Sequential Receipt Chain & Total Calculation

Append: O(1) • Sequential Sum: O(N)

As each car completes service, a new ReceiptNode is chained to the tail of a Singly Linked List. Unlike fixed arrays, a Linked List provides dynamic node allocation where each receipt node holds its transaction payload and a reference (.next) to the subsequent car's receipt. At the shift Finish Point (10 cars served), the attendant opens the Station Computer and performs an $O(N)$ pointer traversal from HEAD to TAIL to sum the total cash amount and verify the accounts!

receiptList.append(sale); // Node added at tail in O(1) time
while (curr) { total += curr.total; curr = curr.next; } // O(N) settlement sum

Shift Guidelines

  • Serve vehicles in the order of the FIFO queue.
  • Check the customer's requested fuel type carefully! Wrong fuel causes penalties.
  • Hold pump until requested litres are reached — it auto-stops when full.
  • Don't let waiting customers' patience hit 0% or they will walk out angrily.
